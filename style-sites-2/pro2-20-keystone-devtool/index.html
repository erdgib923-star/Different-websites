How it works

One commit in, one honest diff out.

  1. Read. Springline parses the config you changed.
  2. Plan. It asks each provider what would actually happen.
  3. Show. You get the result as a diff, on the pull request.

Changelog

Shipped lately

  1. v2.6.0 21 Oct 2026

    Plan comments on pull requests

    Every pull request gets a plan comment that updates in place when you push again.

  2. v2.5.2 30 Sep 2026

    Faster plans for big monorepos

    Only the services a commit touches are planned. A 300-service repo went from 4 min to 22 s in our tests.

  3. v2.5.0 2 Sep 2026

    Cost line on every plan

    Each plan shows the expected monthly cost change next to the diff.

  4. v2.4.0 5 Aug 2026

    Policy checks

    Write rules like "nothing public in prod" and Springline blocks plans that break them.
